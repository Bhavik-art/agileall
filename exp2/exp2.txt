# Experiment 2: To Perform Version Control Operations Using Git

## Aim
To understand a Version Control System (VCS) and perform basic version control operations using Git.

## Objectives
1. Install and configure Git.
2. Create a GitHub account.
3. Understand version control and source code management.
4. Create a local Git repository.
5. Track changes using Git.
6. Commit changes and inspect project history.
7. Create branches and understand how branches support independent development.
8. Connect a local Git repository to GitHub and push code to a remote repository.

## Theory

### Version Control System (VCS)
A Version Control System records changes to a file or set of files over time so that earlier versions can be inspected or restored. It helps developers track project history and collaborate safely.

A centralized VCS stores versions on a central server. Developers check out files, make changes, and send their changes back to the server.

### Source Code Management
A Source Code Management (SCM) system coordinates the coding work of a software development team. It may also be called a version control system or source control system. Examples of source-control platforms and tools include GitHub, Bitbucket, and Apache Subversion.

### Git and GitHub
Git is a distributed version control system that tracks changes in files on a local computer. GitHub is an online platform for hosting Git repositories and collaborating with others. Git and GitHub are related, but they are not the same tool.

## Requirements
- Windows computer
- Internet connection
- Git: https://git-scm.com/downloads
- GitHub account: https://github.com/join
- Optional code editor: https://code.visualstudio.com/

## Step-by-step implementation

### Step 1: Download Git
1. Open the official [Git downloads page](https://git-scm.com/downloads).
2. Select the Windows download.
3. Wait for the installer to download.

### Step 2: Install Git on Windows
1. Open the downloaded installer.
2. Approve the Windows User Account Control prompt if it appears.
3. Review the licence and click **Next**.
4. Keep the default installation location unless you have a specific reason to change it.
5. Keep the recommended default components and continue.
6. Select your preferred text editor for Git.
7. Choose the initial branch name option. You can use `main` for new repositories if the installer offers that choice.
8. Keep the recommended PATH option so Git can be used from a terminal.
9. Keep the default SSH executable and HTTPS transport settings unless your environment requires otherwise.
10. Keep the recommended line-ending, terminal, pull, and credential-helper options.
11. Click **Install**, wait for the installation to finish, and click **Finish**.
12. Open **Git Bash** from the Windows Start menu.

### Step 3: Verify Git installation
Run the following commands in Git Bash or a terminal:

```bash
git --version
git --help
```

The first command should display the installed Git version.

### Step 4: Configure your Git identity
Configure the name and email that you want recorded in your commits. Use your own details; the values below are examples.

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global --list
```

These settings label commits. Use an email address you are comfortable associating with your GitHub activity.

### Step 5: Create a GitHub account
1. Open [GitHub Join](https://github.com/join).
2. Enter the requested account details.
3. Complete the verification step.
4. Create the account and verify your email using the code sent by GitHub.
5. Follow the setup prompts and select a plan. The Free plan is sufficient for this lab.
6. Sign in to your new account.

Never share your password or verification code with anyone.

### Step 6: Create a local project folder
Create a folder named `git-version-control-lab`, then open Git Bash or a terminal inside it.

```bash
mkdir git-version-control-lab
cd git-version-control-lab
git init -b main
```

If your installed Git version does not support `git init -b main`, use `git init` and then run `git branch -M main`.

### Step 7: Create a sample file
Create a `README.md` file with a short project description. You can create it in a text editor or use the following command in Git Bash:

```bash
echo "# Git Version Control Lab" > README.md
echo "This repository demonstrates basic Git operations." >> README.md
```

### Step 8: Check repository status and stage files
Use `git status` to see which files are untracked or modified. Then stage the README file:

```bash
git status
git add README.md
git status
```

`git add` stages changes so they can be included in the next commit.

### Step 9: Commit the first version
Save the staged changes in the repository history:

```bash
git commit -m "Initial commit: add README"
git log --oneline
```

A commit records a snapshot of the staged changes with a message.

### Step 10: Modify a file and inspect changes
Add another line to `README.md`, then inspect the difference:

```bash
echo "Git records changes over time." >> README.md
git diff
git status
git add README.md
git commit -m "Update README with Git information"
git log --oneline
```

`git diff` displays unstaged changes. After staging, use `git diff --staged` to inspect what is staged for commit.

### Step 11: Create and switch to a branch
Branches let you work on a change without making it directly on the main branch.

```bash
git switch -c feature/lab-notes
echo "Branch practice completed." >> README.md
git add README.md
git commit -m "Add branch practice note"
git branch
git log --oneline --all
```

Return to the main branch:

```bash
git switch main
```

The branch-specific commit remains on the feature branch. This step demonstrates branching; it does not merge the feature branch.

### Step 12: Create a GitHub repository
1. Sign in to [GitHub](https://github.com/).
2. Select **New repository**.
3. Enter `git-version-control-lab` as the repository name.
4. Choose the visibility appropriate for your lab (Public or Private).
5. For this local-first exercise, do not initialize it with a README, licence, or `.gitignore`, because the local repository already has a commit.
6. Create the repository and copy its HTTPS repository URL.

### Step 13: Connect the local repository to GitHub
Replace `YOUR-USERNAME` with your GitHub username if using the example URL.

```bash
git remote add origin https://github.com/YOUR-USERNAME/git-version-control-lab.git
git remote -v
git push -u origin main
```

If GitHub shows a different repository URL, use the exact URL shown on your repository page. GitHub may prompt you to authenticate using its supported sign-in flow or credential manager.

### Step 14: Verify remote version control
1. Refresh the GitHub repository page.
2. Confirm that `README.md` is visible.
3. Check that the commit history is present.
4. After switching to `main`, confirm that the `main` branch is selected on GitHub.
5. Make a small local change, commit it, and push it to confirm the workflow.

```bash
git switch main
echo "Remote sync verified." >> README.md
git add README.md
git commit -m "Verify remote synchronization"
git push
git status
```

After a successful push, `git status` should report that the local branch is up to date with its remote tracking branch.

## Common Git commands

| Command | Purpose |
|---|---|
| `git --version` | Check the installed Git version |
| `git init` | Initialize a local repository |
| `git status` | Show working-tree and staging status |
| `git add <file>` | Stage a file |
| `git commit -m "message"` | Record staged changes |
| `git log --oneline` | View compact commit history |
| `git diff` | View unstaged changes |
| `git branch` | List local branches |
| `git switch <branch>` | Switch branches |
| `git remote -v` | Show configured remote repositories |
| `git push` | Send local commits to a remote |
| `git pull` | Fetch and integrate remote changes |

## Conclusion
A Version Control System helps track, manage, and recover changes to files over time. Git provides distributed version control on a local computer, while GitHub hosts Git repositories online and supports collaboration. The experiment demonstrates how Git operations can be used to maintain project history and share code.

## Viva questions and answers

### Q1. What is a Version Control System?
A Version Control System (VCS) is a tool that tracks, manages, and records changes made to files or source code over time. It maintains project history and can help developers inspect or restore earlier versions.

### Q2. What is the difference between Git and GitHub?
Git is a distributed version control system used to track changes and maintain history on a computer. GitHub is an online platform used to host Git repositories and collaborate with others. In simple terms, Git is the version-control tool, while GitHub is a platform for sharing and managing repositories online.
